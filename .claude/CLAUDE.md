# Project Instructions

This is a **luxury real-estate marketplace** on the Next.js App Router. It serves a public marketing site plus three authenticated portals — buyer (`/dashboard`), agent (`/agent`) and admin (`/admin`) — against the NestJS backend in `../backend`.

## Non-negotiable rules

1. **No comments in code.** Ever. Code reads clearly on its own — when it doesn't, the abstraction is wrong. Fix the abstraction.
2. **No hardcoding.** API routes, durations, enums, and copy that appears twice live in `lib/constants.ts` or feature-scoped `lib/config/<feature>.ts`. Endpoints come from `config.api.*`, shapes from Zod schemas. Sample and placeholder content lives in `lib/data/`, never inline in a page.
3. **No `any` in TypeScript.** Use `unknown` + narrowing or a precise type. Derive types from Zod with `z.infer`.
4. **Match the existing architecture.** Do not invent patterns, and do not invent locations — when you are unsure where something goes, re-read this file. State the reason before deviating.
5. **Single source of truth.** Name a recurring decision once as a semantic token and reference it everywhere. Define once, change in one place.
6. **Minimize LOC.** Ship the shortest solution that stays maintainable.
7. **No `console.log`, `console.error`, or debug statements** in committed code. Logging belongs in services.

## The enum mirror

`lib/enums/enums.ts` mirrors the backend by hand. Thirty of its `as const` arrays name an `enum` block in `../backend/prisma/schema.prisma`, and `lib/validations/` feeds those arrays straight into `z.enum`, so a member the backend has and the mirror lacks is not a cosmetic gap — the response fails to parse. The other arrays (`PROPERTY_SORTS`, `TIME_FILTERS`, `MODERATION_DECISIONS`, `SERVICE_STATES`, `INTEGRATION_IDS`) are UI vocabulary with no backend counterpart and are deliberately unmapped. `DISPUTE_OUTCOMES` is the one exception: it mirrors a DTO enum, not a Prisma one, so the parity gate cannot see it, and `lib/validations/dispute.test.ts` holds it to the generated contract instead.

Parity is not left to memory: `pnpm enums:check` reads both files, compares members for every mapped pair, and fails when they disagree. It is part of the push gate below. The pairing is the explicit table in `tools/enum-parity.mts` — never a naming heuristic, because `CONTINGENCIES`/`Contingency` and friends do not survive one. Adding an array that mirrors a new Prisma enum means adding it to that table; a member the UI genuinely should not carry means dropping the pair from it, with the reason stated here.

A missing schema skips the check rather than failing it, so the gate never blocks a frontend cloned without its sibling backend.

**Any script that maintains a committed artifact from a source outside it gets this treatment** — a check twin that re-derives, diffs, and exits non-zero, listed in the push gate. Regeneration and hand-mirroring are never left to memory.

## File rules

- **One component per file.** Kebab-case filename matching the export (`stat-grid.tsx` → `StatGrid`). The one exemption is a compound primitive in `components/ui/`: `menu.tsx` may carry `MenuContent` beside `Menu`, because a primitive family is consumed as one unit. Everywhere else, prefixing a helper with the file's name does not make it a part — it gets its own file.
- **Absolute imports via `@/`.** Never deep-relative (`../../../lib/...`).
- **Any file over ~150 lines gets split**, `page.tsx` included. Derivation logic moves to `lib/data/`, JSX to `components/`. The rule targets complexity, not length: `lib/enums/enums.ts` is exempt, because a flat list of enum literals and their label maps has no seam to split on and dividing it by domain would scatter one lookup across five files. Any other exemption gets written here before it is taken.
- **Add packages with `pnpm add`.** Never hand-edit `package.json`.
- **A flow that moves money gets written acceptance criteria before it gets tests.** `docs/archive/MONEY_PATH.md` is the pattern: criteria numbered, tests named after them.

## Before you commit or push

Git hooks are **disabled**. `.husky/` is kept but not installed: the `prepare` script unsets `core.hooksPath` on every `pnpm install`, so nothing runs on commit or push.

- **Commit** — `.husky/pre-commit` would run `pnpm lint-staged`: `eslint --fix` then `prettier --write`, over staged files only.
- **Push** — `.husky/pre-push` would run `pnpm type-check`, then `pnpm lint`, then `pnpm enums:check`, then `pnpm contract:check`. This is the real gate.

Run those by hand when you want the gate. To re-enable the hooks, set `prepare` back to `husky` and run `pnpm install`.

The rules above are not restated here. They bind every edit, not the gate.
