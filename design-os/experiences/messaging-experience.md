# Messaging Experience

---

# 1. Experience Overview

## Purpose

The Messaging Experience enables secure, contextual, and efficient communication between buyers and sellers throughout the property lifecycle.

Messaging is not simply a chat feature.

It is the primary collaboration workspace where questions are answered, negotiations occur, viewings are coordinated, documents are shared, and trust is established.

The experience should feel:

- Immediate
- Professional
- Organized
- Transparent
- Context-aware

Users should never lose context about what property or transaction a conversation relates to.

---

# 2. Primary Users

Messaging serves:

- Buyers
- Sellers
- Administrators (future moderation)

Every conversation should be tied to a business objective rather than casual communication.

---

# 3. User Goals

Users want to:

- Ask questions about properties.
- Respond quickly.
- Schedule viewings.
- Negotiate offers.
- Share information.
- Track previous conversations.
- Stay informed.
- Reach agreements efficiently.

Messaging exists to move users closer to completing a transaction.

# 7. Experience Principles

## Context First

Every conversation should clearly identify:

Property

Participants

Current transaction stage

Conversation status

Users should never ask:

"Which property is this about?"

---

## Communication Before Navigation

Users should perform common tasks without leaving the conversation.

Examples:

View property summary.

View seller profile.

View buyer profile.

Schedule viewing.

Accept viewing.

Submit offer.

Review offer.

Open transaction.

Messaging becomes the control center.

---

## Conversation Organization

Messages should be easy to scan.

Group messages logically.

Separate system events from user messages.

Highlight important updates.

Surface unread conversations.

Pin active negotiations.

---

## Transparency

Users should understand:

Who sent the message.

When it was sent.

Delivery status.

Read status.

System events.

Offer updates.

Viewing updates.

Nothing should feel hidden.

---

## Persistence

Conversations become part of the transaction history.

Users should always be able to revisit previous discussions.

Messages should feel permanent and trustworthy.

# 13. Notification Philosophy

Notify users only when action is valuable.

Examples:

New message

Viewing confirmed

Offer received

Offer accepted

Offer rejected

Document shared

Transaction updated

Avoid notification fatigue.

Notifications should prioritize urgency.
