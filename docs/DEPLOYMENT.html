What changed Three assumptions that no longer hold

Each of these breaks a different part of this app, and none are reflected in the guides still circulating.

Withdrawn · 1 Aug 2026

DigitalOcean's $200 credit no longer exists

DigitalOcean wound down its Pack participation, and every credit — including already-redeemed ones — expired on 1 August 2026. It is absent from the current partner list. Any walkthrough that opens with "spin up a $6 droplet" is describing a door that is now locked.

Free tier retired · May 2025

SendGrid costs money, and this API refused to boot without it

Twilio retired SendGrid's free plan; what remains is a 60-day trial, then $19.95/month. env.validation.ts marked SendGrid requiredInProduction: true, so a production boot without a key failed at startup rather than degrading quietly. Nine services depended on it.

Still good · The offer that carries the app

Heroku pays for compute and database in full

$13/month for 24 months, spendable on dynos, Postgres and Key-Value — the exclusion is third-party add-ons. A Basic dyno ($7) never sleeps, unlike Eco; Postgres Essential-0 ($5) gives 1 GB. That is $12 against a $13 credit, and it is the only always-on compute-plus-database offer left in the Pack.

Blockers found Three · all resolved in the working tree

Each would have failed only after an evening already spent on dashboards. Nothing here is committed yet.

01 · Would fail at boot

Production start required a SendGrid key that costs money

Was: env.validation.ts listed SendGrid as required in production, and SendGrid's free tier no longer exists.

Now: the mailer is provider-neutral and speaks SMTP through nodemailer — already present in dependencies, so nothing new was installed. The credential group became SMTP_HOST / SMTP_USER / SMTP_PASSWORD / EMAIL_FROM, and Resend became a config value rather than a code dependency. Every public method kept its signature, so all nine call sites were a rename.

✓ 83/83 tests pass · type-check and lint clean
02 · Would fail on every deploy

Heroku prunes the Prisma CLI before migrations run

Was: no Procfile, so migrations never applied — and worse, Heroku prunes devDependencies at the end of the build while the release phase runs after the prune. prisma is a devDependency, so migrate deploy would have failed on the first push.

Now: a Procfile with a release: line, an app.json declaring the add-on and every config var with its reason, engines.node and packageManager so Heroku selects Node 22 and pnpm 10, and PNPM_SKIP_PRUNING=true documented as non-optional.

✓ Procfile · app.json · engines pinned
03 · Would fail silently, in one half

The proxy needs a key the env template never mentioned

Was: proxy.ts verifies session cookies with JWT_PUBLIC_KEY, absent from .env.example. On Vercel it would have been skipped — and the failure is deceptive: the public site keeps working while all three portals bounce to /login, which reads like an auth bug rather than a config one.

Now: documented in the template with why it exists and the warning that the private half must never reach Vercel.

✓ Documented · backend CI workflow added — there was none
Audited · clean

No secrets are tracked in either repository

docs/storage/ holds the Proton recovery phrase and 2FA codes. They are matched by .gitignore:27 and untracked, and no .env file is tracked in either repo — safe to make both public.

Deploy walkthrough Eight phases · order is load-bearing

The two hosts reference each other, and NEXT_PUBLIC_* values are inlined at build time rather than read at runtime — so a value corrected after the build does nothing until you redeploy.

01
Before any hosting · 20 min

Claim the domain and verify it for email

Everything downstream keys off the hostname, and Resend will not send at all until a domain is verified — there is no shared-sender fallback, even on the free plan. Claim it first so DNS propagates while you work.

  • Name.com is the pick — 25+ extensions including .studio, against Namecheap's .me only. Log out of Name.com first, then enter through the Pack offers page, or the promo silently fails to apply.
  • Move nameservers to Cloudflare (Domains → Onboard a domain), and keep every record grey-cloud. Vercel does not support a reverse proxy in front of it — orange cloud produces Error 526 and stacks a second CDN on its own. Disable DNSSEC at the registrar before switching nameservers.
  • Add Resend's DKIM and SPF records now, so verification completes before Phase 04.
02
Credentials · 15 min

Generate keys and collect third-party secrets

The RS256 pair is generated locally, never bought. The public half goes to both hosts; the private half only ever reaches Heroku. 

# in backend/
pnpm keys:generate

Then collect the Stripe secret key, the Cloudinary trio, and a Resend API key (re_…) — copy it at creation, it is shown once.

03
Redeem the credit · 10 min

Create the Heroku app and attach Postgres

Redeem the Heroku offer from the Pack dashboard first — credits apply to the account, not the app. Heroku still wants a card on file to provision add-ons even when credits cover the bill. 

heroku create keyhold-api --stack heroku-24
heroku addons:create heroku-postgresql:essential-0 --app keyhold-api
heroku ps:type web=basic --app keyhold-api

DATABASE_URL is set by the add-on. Do not set it yourself.

04
Config · 15 min

Set every config var, then push

NODE_ENV=production arms the credential checks, so a half-configured deploy fails loudly at startup instead of swallowing emails. That is the behaviour you want — do not weaken it to get a green deploy. 

heroku config:set --app keyhold-api \
  NODE_ENV=production \
  PNPM_SKIP_PRUNING=true \
  JWT_PRIVATE_KEY="$(cat jwt-private.b64)" \
  JWT_PUBLIC_KEY="$(cat jwt-public.b64)" \
  FRONTEND_URL="https://keyhold.example" \
  SMTP_HOST=smtp.resend.com SMTP_PORT=465 SMTP_USER=resend \
  SMTP_PASSWORD="re_..." EMAIL_FROM="noreply@keyhold.example" \
  STRIPE_API_KEY="sk_live_..." STRIPE_WEBHOOK_SECRET="whsec_..." \
  CLOUDINARY_CLOUD_NAME=... CLOUDINARY_API_KEY=... CLOUDINARY_API_SECRET=...

git push heroku master
heroku logs --tail --app keyhold-api

The release phase runs prisma migrate deploy before the new dyno takes traffic. Confirm at /api/health — it returns 503 when the database is unreachable, which makes it a valid uptime-monitor target.

05
Web · 10 min

Deploy the frontend to Vercel

Import the repo, confirm the install command is pnpm install --frozen-lockfile, and set every variable from .env.example for Production and Preview. Three decide whether the app works at all:

  • NEXT_PUBLIC_API_BASE_URL — the Heroku origin including /api. It also feeds the connect-src directive, so a wrong value surfaces as a blocked browser request, not a build error.
  • NEXT_PUBLIC_SITE_URL — drives canonical URLs, Open Graph, sitemap.ts and robots.txt.
  • JWT_PUBLIC_KEY — the only non-public variable here, and the one from Blocker 03.

Leave DOCKER_BUILD and NEXT_PUBLIC_DEV_QUICK_LOGIN unset.

06
Cutover · 10 min

Point the hosts at each other, then at the domain

This is the step people repeat three times. FRONTEND_URL on Heroku is the CORS allow-list in main.ts and must match the web origin exactly, scheme included.

  • Attach keyhold.example to Vercel and api.keyhold.example to Heroku.
  • Reset FRONTEND_URL on Heroku to the final origin.
  • Reset NEXT_PUBLIC_API_BASE_URL on Vercel and redeploy — it is inlined at build time.
  • Repoint the Stripe webhook and update STRIPE_WEBHOOK_SECRET.
07
Before you trust it · 15 min

Schedule backups, because this tier cannot roll back

Essential-tier Postgres has continuous physical backups but no rollback — that starts at Standard. pnpm db:backup is not a fallback: it shells out to pg_dump, which is not installed on this machine. Heroku's scheduler is the recovery path. 

heroku pg:backups:schedule DATABASE_URL --at "02:00 UTC" --app keyhold-api
heroku pg:backups:capture --app keyhold-api
heroku pg:backups:download --app keyhold-api

Heroku keeps the last 7 daily backups. Capture one by hand before any destructive migration. Seed only deliberately — the seed owns seed- prefixed rows, and db:reseed and db:purge must never run against production.

08
The gate you already documented

Close the escrow authorisation gap

REMAINING_WORK.md names this as the one thing blocking shipping: the buyer-facing release path is covered against MONEY_PATH.md, but the server-side rules deciding who may release a hold, and when, have no tests. Everything above is infrastructure; this decides whether real money should move through it. Ship the marketing site and portals on live data first if you want a public URL sooner — but do not enable live Stripe keys until this is covered.

Month 24, planned now Three moves · one needs upkeep

The credit ends and the bill becomes $12/month. The reason to name the options today is that only one of them asks anything of you in the meantime.

Option A · no work

Pay it

$12/month for a running marketplace is the cheapest outcome and needs nothing from you.

Option B · the exit you already hold

Move to Azure

The $100 credit is unredeemed and buys roughly seven months on Container Apps plus Postgres Flexible Server. backend/Dockerfile already builds a standalone image, so this is a real option rather than a rewrite.

Option C · split it

Keep the dyno, move the database

Move Postgres to a provider with a durable free tier. Watch latency — cross-region round-trips will show up in every Prisma query.

The upkeep

Keep the Docker setup green

Neither Heroku nor Vercel uses it — Heroku builds from the buildpack, Vercel from its own pipeline. Keep docker-compose.yml working anyway. It is what makes month 24 a decision instead of an emergency.
